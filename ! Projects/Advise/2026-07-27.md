# 1. Arsitektur & Database

## Manajemen Organisasi

- Menambahkan tabel **Organization**.
- Satu deployment hanya berlaku untuk **satu Organization**.
- Struktur relasi diperbarui menjadi:
  - **Organization** → memiliki banyak **Projects**
  - **Project** → memiliki banyak **Domains**

## Identity and Access Management (IAM)

- Relasi antara tabel **User** dan **Role** diubah menjadi **Many-to-Many**.
- Menambahkan tabel baru untuk **Permission/Authorization** yang akan dihubungkan dengan setiap Role.

## Standarisasi Kolom

Setiap tabel wajib memiliki field berikut:

- `created_at`
- `updated_at`
- `updated_by`

## Manajemen Scan & Report

### Scan

- Menambahkan tabel **Scan** untuk mencatat setiap iterasi proses scanning.
- Tabel **Scan** harus terhubung dengan **Users** agar dapat mengetahui siapa yang menjalankan scan.

### Report

- Relasi **Report** diubah:
  - Sebelumnya → `Report → Domain`
  - Menjadi → `Report → Scan`

### AI Generated Report

- Menambahkan tabel khusus untuk menyimpan hasil laporan yang dihasilkan AI.

## Struktur Payload

### Payload Category

- Kategori payload dipisahkan ke tabel tersendiri (tidak lagi berada di tabel Payload).

### Penyimpanan Payload

- Untuk sementara seluruh data payload akan disimpan langsung di database.

### Vulnerability Category

- Menambahkan field:
  - `mitigation`

# 2. Peningkatan Fitur Scanning & Crawler

## Scan Mode

Menambahkan field baru pada tabel **Payload** untuk menentukan mode scanning.

Mode yang tersedia:

- Lightweight
- Fast
- Balanced
- Deep

## Payload Rules

Menambahkan tabel baru untuk menyimpan:

- Conditions
- Severity Rule

## Scan Depth

- Scan depth ditentukan berdasarkan panjang URL (jumlah karakter `/`).

## Crawling & Enumerable

### Enumerable Detection

Menambahkan regex untuk mengenali:

- Angka
- GUID
- Format enumerable lainnya

### Maximum Enumerable

Menambahkan konfigurasi:

- `maximum_enumerable`

Tujuannya adalah membedakan:

- Parameter dinamis
- Endpoint statis

### Endpoint Information

Setiap endpoint hasil crawling wajib menyimpan informasi:

- HTTP Headers

## Incremental Scanning

- Status: **Postponed**

# 3. Deployment, Keamanan & Skema Lisensi

## Proteksi Source Code

Komponen berikut wajib diproteksi dari reverse engineering:

- Crawler
- Scanner
- Payload

> Catatan: Mekanisme proteksi (misalnya enkripsi atau obfuscation) masih akan ditentukan.

## Deployment

- User tidak diberikan akses untuk melakukan deployment secara mandiri.

## Tiering Lisensi (Packaging)

Deployment akan dibagi ke beberapa paket lisensi.

Setiap paket dapat membatasi:

- Kecepatan scanning
- Alokasi memori
- Jumlah domain yang dapat discan
- Maksimum waktu crawling
- Maksimum jumlah endpoint
